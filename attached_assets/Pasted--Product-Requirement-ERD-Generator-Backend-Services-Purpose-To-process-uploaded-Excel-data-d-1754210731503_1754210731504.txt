🔧 Product Requirement: ERD Generator – Backend Services
🧭 Purpose
To process uploaded Excel data dictionaries, extract structured metadata (tables, attributes, and foreign key mappings), and return valid Mermaid syntax representing an ERD. The backend handles parsing logic, FK relationship inference, and prepares JSON/Mermaid outputs that power the frontend renderer and code viewer.

In MVP, the backend may be optional (fully frontend-parsed), but this backend will be useful for:

Uploading large Excel files (>2MB)

Decoupling logic from UI

Preparing for SaaS deployment (auth, audit logs, history)

🔌 Core API Endpoints
Endpoint	Method	Purpose
/api/parse-excel	POST	Accepts uploaded .xlsx file; returns normalized JSON of tables, attributes, and FK relationships
/api/generate-mermaid	POST	Accepts parsed JSON; returns Mermaid erDiagram block
/api/health	GET	Returns server health status (for CI/CD + deploy checks)

📦 Modules and Services
1. Excel Parser Service
| Input | Raw .xlsx file |
| Library | xlsx (SheetJS) |
| Logic |

Parse TableMetadata and AttributeMetadata sheets

Normalize column names (case-insensitive matching)

Validate required fields: Physical Table Name, Attribute Name, Type

Mark PKs: if Is Autonumber = true AND Attribute Name = "Id"

Mark FKs using Reference Table + Column Table

Output consistent structure:

json

    }
  ]
}
2. Mermaid Generator Service
| Input | Parsed table metadata (JSON) |
| Output | Mermaid erDiagram block |
| Logic |

Convert each table to a Mermaid entity block

Format columns with datatype and FK/PK annotations

Add FK edges like:
Order }o--|| User : "FK UserId"

Ensure Mermaid syntax is deterministic and readable

Wrap output as:

📐 Design & Code Practices
Area	Guideline
Input validation	Strict typing + detailed error messages
Security	Use multer or busboy with file type check
Performance	Memory-only processing; no disk write required
Logging	Console log with status codes + summary (basic winston log if needed)
Mermaid style	One table per block, one FK per line, avoid line breaks in labels

🧠 MVP Logic Assumptions
Assumption	Behavior
Missing Reference Table or Column Table	FK skipped with warning; diagram still builds
Multiple FKs to same table	All relationships rendered
Table with no attributes	Skipped or flagged (depends on config)
Non-entity Data Kind in TableMetadata	Ignored (only entity used)
